## 5. NFR 성능·보안 시험

### 5.1 정지, 세션과 현재 기기 로그아웃

- **[기획] 정지 차단** (`TP-I-SEC-002-01`, `TP-C-SEC-002-01`, `TP-E-SEC-002-01`). 나루·Litpage 세션을 열고 별도 관리자 계정으로 정지를 확정한다. 정지 커밋만으로 열린 세션은 즉시 종료되지 않으며 백채널 통지를 보내지 않는 것이 09의 시험 전제다. 한 시도의 영향이 다른 판정을 가리지 않도록 독립 세션에서 Google 재로그인, 나루 세션 갱신, OP authorize, OP token의 코드 교환과 갱신, UserInfo, 기존 세션으로 Litpage 신규 진입·문서 열기를 각각 시도한다. 각 경계에서 차단과 07·09의 오류를 확인하고 정지 해제 뒤 로그인 성공을 본다. 통합 시험은 최신 회원 상태를 기준으로 판정하고 정지 확정 후 오래된 상태로 발급되지 않는지 확인한다. **[제안값 PV-018]** 정지 저장 확정에서 새 로그인 차단까지 ≤5초. 열린 세션이 갱신 시 차단되기까지의 최대 시간은 Q-087 [미확인]이다. [DEC-098](../01-planning/02-decision-log/decision-log.md), [04 §4.4](04-NFR-technical.md), [09 §3~4·9](09-auth.md)
- **[기획] 통합 로그아웃** (`TP-I-AUTH-002-01`, `TP-C-AUTH-002-01`, `TP-E-SEC-001-01`). 한 회원으로 기기 A·B의 나루 및 Litpage 세션을 준비한다. A의 나루에서 시작하면 현재 세션 및 연결 자격이 폐기되고 백채널로 같은 `sid`의 Litpage 세션·웹소켓이 종료된다. **[제안]** A의 Litpage에서 시작하면 RP-Initiated Logout으로 나루의 현재 세션을 폐기하고 백채널로 Litpage의 세션·웹소켓을 종료한다. 양 경로에서 A의 새로고침·이전 쿠키·Litpage 재진입·웹소켓 후속 작업 거부와 B의 두 세션 유지를 확인한다. 이미 종료된 상태, 확인 취소, 전달 재시도·중복 수신, 지연 콜백·갱신 응답과 폐기 기록의 경합도 09 §5에 맞춰 확인한다. [DEC-094](../01-planning/02-decision-log/decision-log.md), [09 §5·9](09-auth.md)
- **[제안값 PV-017·028]** 경로별 30회에서 응답 후 접근 거부·연결 종료까지 전파 최댓값 ≤5초와 API p95 ≤2초를 판정한다. Litpage 시작 경로의 API 시간은 OP 확인 제출부터 재며 사용자 확인 대기 시간은 제외한다. **[제안]** 요청 ID와 서버 커밋·판정 시각, 클라이언트 단조 시계를 대조한다. 신뢰할 공통 기준을 확인한 경우에만 서로 다른 시계의 값으로 차이를 계산한다. 로그·증적은 자격 원문 없이 남긴다. [04 §4.4·6](04-NFR-technical.md), [09 §9](09-auth.md#9-pv-017--pv-018-시험-방법)
- **[기획] 세션 수명** (`TP-U-SEC-006-01`, `TP-I-SEC-006-01`). 주입 시계로 유휴 7일 직전의 활동과 7일 무요청 만료, 계속 활동 중 절대 30일 만료를 검증한다. **[제안]** `TP-C-SESSION-CSRF`에서 07의 두 보안 스킴이 함께 필요한 변경 요청을 검사한다. 갱신 후 새 쿠키·CSRF가 유효하고 이전 값은 거부되며 절대 만료 기준은 유지되는지 확인한다. [DEC-092](../01-planning/02-decision-log/decision-log.md), [04 PV-029](04-NFR-technical.md), [07 OpenAPI](07-api/openapi.yaml), [09 §2~3](09-auth.md)

### 5.4 Markdown·CSV 무손실 왕복 스파이크

**[제안]** `TP-E-LITPAGE-ROUNDTRIP`은 구현 전 E2E 스파이크다. 편집 가능한 문서·표를 지정 드라이브 폴더에 Markdown·CSV로 저장하고, 원본 SQLite 레코드에 의존하지 않는 환경에서 저장 파일과 부가 파일만으로 재열기한다. 다시 편집·저장해 두 번째로 재열고 변경분과 나머지 속성을 비교한다. 일반 문서·하위 페이지, 리치텍스트·첨부, 인라인·전체 페이지 DB와 행 페이지, 댓글이 달린 문서, 권한이 다른 문서·DB 속성을 각각 포함한다. [04 §4.1·GAP-025](04-NFR-technical.md), [09 머리말·§11](09-auth.md), [ADR 0004 왕복 스파이크](../decisions/0004-auth-idp-litpage.md#무손실-왕복-검증-스파이크)

합격은 모든 유형이 편집 가능하고 두 번의 재열기 모두에서 ADR 0004의 비교 속성 누락·변형·오연결 및 권한 밖 데이터 노출이 0건인 경우다. 식별자를 재할당할 경우 원래 식별자와 일대일로 대응하고 참조를 일관되게 복원한다. 결과가 미검증이거나 실패하면 채택을 보류하며, **왕복 검증을 통과해야 저장 형식을 채택**한다. 비교 기준은 ADR 0004의 표를 따르고 측정 도구·세부 비교 방법·패키징 형식과 전체 보존 범위, 자동 저장 지연·재시도·실패 정의·1 GiB 적용은 [미확인]이다. [ADR 0004 왕복 스파이크](../decisions/0004-auth-idp-litpage.md#무손실-왕복-검증-스파이크), [09 §11](09-auth.md#11-남은-미확인), [13 §3.4](13-cutover.md#34-확인과-개방)
