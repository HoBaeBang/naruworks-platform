# Naru Calendar 구현 현황과 로드맵

## 완료한 범위

- 개인 캘린더 다중 생성과 기본 캘린더 지정
- 공유 캘린더, 역할 기반 권한, 7일 만료 초대 링크, 소유권 이전
- 단일·종일·기간·반복 일정과 회차 예외
- 공휴일·음력 날짜 메타데이터와 운영 예외
- 연간·월간·주간·일간 보기, 모바일 반응형·스와이프 탐색
- 여러 Google 계정 연결, 하위 캘린더 선택, 읽기 전용 저장본
- 30분 주기 증분 동기화, 실패 표시·수동 재시도·연결 해제

## 현재 보류 범위

| 항목 | 보류 이유 |
| --- | --- |
| Google 양방향 동기화 | 수정 충돌, 삭제 전파, 반복 원본·회차 매핑을 별도 설계해야 함 |
| 참석자·알림 | 초대·알림 전달 채널과 권한 정책이 필요 |
| 드래그 앤 드롭 | 모바일·반복·기간 일정의 조작 규칙을 먼저 정의해야 함 |
| 검색 | 검색 범위와 개인정보 노출 기준을 정해야 함 |
| 다중 backend 동기화 | 다중 인스턴스가 필요해질 때 분산 잠금·queue를 도입 |

## 다음 작업 원칙

Calendar 변경은 기능 하나당 작은 이슈를 만들고 `feature/NARU-이슈번호-짧은-영문-설명` 브랜치에서 진행한다. PR은 `develop`을 대상으로 하며, 변경된 정책이 있으면 이 디렉터리 문서도 함께 수정한다.

GitHub 절차는 [GitHub 작업 런북](../../development/git-github-session-runbook.md)을 따른다. 변경 이유를 설명하는 학습 자료는 `docs/change-explanations/`에 별도로 남긴다.
