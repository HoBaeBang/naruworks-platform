01 · Background

두 종류의 Google 권한

기존 Google OAuth는 NaruWorks 로그인과 회원 식별용이다. 새 OAuth는 사용자가 원할 때만 Google Calendar 읽기 권한을 부여한다. Calendar 범위를 일반 로그인에 섞지 않기 위해 별도 OAuth 클라이언트와 연결 데이터를 만든다.

02 · Intuition

열쇠를 빌리고 봉인한다

인가 코드는 한 번 쓰는 교환권이다. backend가 이를 Google token endpoint에 보내면 짧게 쓰는 access token과 오래 보관할 refresh token을 받는다. refresh token은 이후 동기화에 필요하므로 DB 평문 저장 대신 AES-256-GCM으로 봉인한다.

03 · Code

의존성 방향으로 읽기

1. 연결은 일정과 분리된 도메인

backend/naru-domain/.../CalendarIntegration.java · backend/naru-infrastructure/.../V13__create_calendar_integrations.sql:1-32

calendar_integrations는 calendar_events와 다르다. 이 분리는 Google 원본 이벤트를 Naru 사용자가 만든 이벤트처럼 실수로 수정하는 문제를 피한다. 회원+제공자 unique 제약은 회원별 Google 연결을 하나로 제한한다.

member_id                  = 연결 소유 회원
encrypted_refresh_token    = 평문 저장 금지
selected_calendar_id       = 다음 단계의 캘린더 선택
last_synced_at / sync_token = 증분 동기화 준비

2. Core 서비스의 업무 규칙

backend/naru-core/.../CalendarIntegrationService.java:33-76

Service는 Google HTTP 규격을 모르고 port만 안다. 인가 코드 교환 후 refresh token이 존재하는지 확인하고, Google 계정 확인과 암호화 후 신규 연결 또는 재연결로 저장한다.

token = exchangeAuthorizationCode(code)
validateRefreshToken(token)
account = findAccount(token.accessToken())
encrypted = encrypt(token.refreshToken())
save(connect or reconnect)
불변식. refresh token이 없다면 저장하지 않는다. access token은 만료되므로 그것만 저장하면 이후 자동 조회가 불가능하다.

3. Infrastructure: Google 규격과 암호화

backend/naru-infrastructure/.../GoogleCalendarOAuthAdapter.java:19-84 · AesGcmSensitiveDataEncryptor.java:24-59

Adapter는 OpenID 기본 범위와 Calendar 목록·이벤트 읽기 범위를 요청한다. access_type=offline은 refresh token을 요구하고 prompt=consent는 재연결 때 동의 과정을 명확히 한다. AES-GCM은 매번 새 12바이트 IV를 사용한다.

GOOGLE_CALENDAR_TOKEN_ENCRYPTION_KEY
  -> Base64 decode -> 정확히 32 bytes -> AES-256 key
DB value = Base64(IV + ciphertext + GCM authentication tag)

4. API: state는 추천 코드가 아니다

backend/naru-api/.../GoogleCalendarIntegrationController.java:35-98

추천 코드는 가입 흐름의 비즈니스 데이터다. 반면 여기의 state는 callback이 정말 이 브라우저에서 시작된 요청인지 확인하는 CSRF 방지용 난수다. callback은 state와 회원 ID를 비교하고 임시 세션 값을 즉시 지운다.

5. Frontend와 운영 설정

frontend/src/components/calendar/calendar-google-integration.tsx:21-76 · .env.example:18-27 · docker-compose.yml backend environment

UI는 연결 계정 이메일만 보여주고 token을 받지 않는다. 연결 버튼은 fetch가 아니라 browser navigation으로 Google 동의 화면을 연다. 키는 Git이 아닌 .env 또는 IntelliJ 환경변수에 둔다. Docker에서는 반드시 backend 컨테이너에 전달되어야 한다.

03A · IMPLEMENTATION BOUNDARY

현재 구현과 다음 단계 구분

현재 구현: OAuth 인가 코드 교환, access token으로 Google 계정 확인, refresh token의 AES-256-GCM 암호화 저장.

아직 미구현: refresh token 복호화, 만료된 access token 갱신, Google 캘린더 목록 조회와 selected_calendar_id 선택, Google 일정 조회·저장·화면 표시.

selected_calendar_id는 사용자가 여러 Google 캘린더 중 NaruWorks에 표시할 하나를 고를 때 저장할 Google의 캘린더 식별자다. 현재는 선택 화면과 조회 API가 없어 null이 정상이다.

증분 동기화는 첫 조회 뒤 Google이 준 sync_token을 저장하고, 다음 조회에서는 그 token 이후 변경된 일정(추가·수정·취소)만 받는 방식이다. last_synced_at과 sync_token은 이를 위한 예약 컬럼이며 현재 사용하지 않는다.
