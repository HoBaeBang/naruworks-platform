## 1. 목표와 배경

Litpage 문서의 Markdown과 표의 CSV를 지정 나루 드라이브 폴더에 저장하고 저장 파일과 부가 파일만으로 두 번 열어 편집 가능한 상태에서 손실 0건인지 검증한다. ADR 0004는 ZIP 사이드카 또는 ZIP 번들을 추천하며 패키징 확정은 왕복 합격에 달려 있다. **[기획]** FR-OSS-003의 지정 폴더 자동 저장과 FR-DRV-005의 드라이브에서 문서 열기를 연결한다. 11은 `TP-E-LITPAGE-ROUNDTRIP`, 기획 AC는 `AC-FR-OSS-003-01`·`AC-FR-DRV-005-01`을 추적한다. [FRD](../../01-planning/frd/FRD.md), [AC](../../01-planning/acceptance-criteria/AC.md), [11 §5.4](../11-test-plan.md#54-markdowncsv-무손실-왕복-스파이크)

| 읽기 전용 참고 | 원문에 있는 동작과 확인 상태 |
| --- | --- |
| 기존 내보내기 | Markdown·표 CSV·행 페이지와 첨부 옵션을 확인했다. CSV는 표시 값, Markdown의 일부 멘션은 표시 텍스트로 나오며 댓글 출력은 HTML 쪽에서 확인된다. [export.ts](../../../services/litpage/apps/server/src/api/modules/export.ts), [render.ts](../../../services/litpage/apps/server/src/content/render.ts) |

### 결론

ZIP 사이드카(사람이 읽는 Markdown·CSV + `model.json`·첨부·SHA-256 바인딩)는 합성 말뭉치에서 1·2차 재열기 구조 동등성을 만족했고, 순수 Markdown/CSV만으로는 고유 속성이 손실된다. 사이드카를 패키징 후보로 고른다. 제품 자동 저장·Litpage 화면 재편집·GAP-025는 이번 실행으로 결정하지 않는다.

### 고른 방식

**ZIP 사이드카.** 읽기 파일 `doc.md` / `sheet.csv` 옆에 `{파일명}.naru-meta.zip`을 둔다. ZIP 안은 `manifest.json`(스키마 `naru.litpage.sidecar.v1`, 패키지 ID, 읽기 파일 SHA-256·크기), `model.json`(정규 모델), `attachments/<id>/<name>`이다. 저장 식별자는 그대로 보존하므로 재할당·역매핑은 필요 없었다. ZIP 번들(한 파일에 읽기 파일+부가 파일)은 같은 모델·해시를 담을 수 있어 무손실 능력은 동등하고, 이번 구현·측정은 사이드카를 기준으로 했다.

### 근거

- 사이드카 경로는 문서·하위 페이지, 리치텍스트(굵게·기울임·취소선·밑줄·코드·색·링크·멘션·날짜·수식), 이미지·첨부 바이트·해시, 인라인 DB(열 타입·옵션 색·수식 정의·결과·관계·롤업·뷰·필터·정렬·그룹·숨긴 열), 행 페이지, 댓글 스레드·인용·해결 여부·반응까지 두 번 연 뒤 `PartialEq`로 원본과 같았다. 대표 편집(제목·본문 런·숫자 셀) 후 새 폴더에서 다시 열어도 변경분과 나머지가 일치했다.
- 시트 CSV는 표시 값만 담고, 서식(`number_with_commas`, 선택지 색), 수식 표현식, 셀 유형, 뷰는 사이드카가 보존했다. 선행 0이 있는 `0123.50`도 숫자 문자열로 유지됐다.
- 순수 Markdown/CSV는 아래 손실이 재현되어 ADR 0004의 무손실 조건을 만족하지 못한다. 일반 편집기가 확장 front matter를 지울 위험은 ADR 기각 사유와 같다.
- 권한 필터를 적용한 내보내기에서는 숨긴 행·속성 값(`숨긴 행`, `권한 밖 급여`, `c-secret`)이 Markdown·CSV·ZIP 목록·model.json 어디에도 없었다. 필터 없이 내보내면 해당 값이 나타나 대조가 유효함을 확인했다.

### 손실·잔여 사례 (숨기지 않음)

| 경로 | 사례 |
| --- | --- |
| 순수 Markdown | 밑줄·글자/블록 색은 CommonMark 문법이 없어 소실. 블록·페이지 ID는 복원 모델이 되지 않음(댓글 줄에 ID 문자열이 남을 수는 있음). 멘션은 표시 링크로만 남고 대상 ID가 1급 필드가 아님. 페이지 메타(작성자·시각·커버), 댓글 스레드 ID·인용·해결·반응, 뷰/필터/정렬/그룹/숨긴 열, 수식 표현식이 없음. |
| 순수 CSV | 수식은 계산 결과만 남고 표현식·열 정의가 없음. 타입은 추론에 의존해 `0123.50`과 수식 결과 `247.00`이 모두 `number_or_numeric_text`로 모호해짐. 뷰·옵션 색·숫자 서식·관계 ID의 구조가 없음. 한글·따옴표·쉼표·내부 줄바꿈의 *표시 값*은 RFC 4180으로 남는다. |
| 사이드카 | 합성 말뭉치의 모델 필드는 손실 0건. 다만 권한 필터가 행을 빼도, 남은 행의 관계 셀이 제외된 행 ID(`row-secret`)를 가리킬 수 있다. 내보내기 계약에서 관계 대상을 함께 지우거나 검사해야 한다. |
| 보존 범위 [미확인] 확인 | 댓글 반응은 사이드카 `model.json`에 넣으면 왕복 보존됐다. 버전 이력, 제안(suggestions), 외부 참조·공유 설정은 이 패키지에 넣지 않았고 드라이브 메타 영역으로 본다. 육안 UI 재편집은 실시하지 않았다. |

### 외부 편집·인코딩·0바이트

- Markdown 또는 CSV만 고치면 SHA-256이 어긋나 `DriftKind::Semantic` 충돌로 감지한다. 사이드카의 정규 모델은 그대로 읽을 수 있다. 사이드카가 없으면 `MissingSidecar`로 실패한다(순수 경로로 자동 강등하지 않음).
- UTF-8 BOM 추가 또는 LF→CRLF만 바꾼 경우는 정규화 텍스트가 같아 `DriftKind::EncodingOnly`로 구분한다. 한글·이모지는 읽기 파일과 모델 모두에서 유지된다. 저장 기본값은 UTF-8(BOM 없음)·LF이다.
- 0바이트 읽기 파일·0바이트 사이드카는 거부한다(DEC-107). 첨부 항목이 비어도 거부한다.

### 크기와 시간 (debug 프로파일, Apple Silicon)

| 말뭉치 | Markdown/CSV | 사이드카 ZIP | 저장 | 열기 |
| --- | --- | --- | --- | --- |
| 기본 합성 문서 | 1,305 B | 3,847 B | (테스트 일괄, 수십 ms 미만) | (동일) |
| 기본 합성 시트 | 359 B | 2,760 B | (동일) | (동일) |
| 확장(하위 페이지 +80, 행 +400) | 48,020 B | 14,704 B | 33.87–36.51 ms | 11.96–12.40 ms |

1 GiB 한도와 자동 저장 지연·재시도는 GAP-025 [미확인]이며 이번 수치로 결정하지 않는다.

### 사용한 crate (Cargo.lock 실제 해상 버전)

`comrak 0.41.1` (인덱스상 최신 major는 1.2.0, 제약 `0.41`으로 0.41.1을 받음), `pulldown-cmark 0.13.6`, `csv 1.4.0`, `zip 2.6.1` (인덱스상 최신 major는 9.8.2, 제약 `2`로 2.6.1을 받음), `serde 1.0.229`, `serde_json 1.0.154`, `sha2 0.10.9`, `thiserror 2.0.21`, `hex 0.4.3`. comrak(GFM 표·취소선·할 일·front matter)과 pulldown-cmark(표·취소선·할 일 이벤트 수 확인)를 순수 Markdown 파싱에 썼다.
