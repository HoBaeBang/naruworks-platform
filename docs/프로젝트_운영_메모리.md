# NaruWorks 프로젝트 운영 메모리

이 문서는 Codex가 새 대화에서 NaruWorks 프로젝트를 이어받기 위해 가장 먼저 읽어야 하는 운영 메모리입니다.

## 프로젝트 정체성

NaruWorks는 개인 홈서버 위에서 여러 웹/앱 서비스를 운영하기 위한 개인 서비스 플랫폼이다.

핵심 메시지:

```text
기획 -> 프론트엔드 -> 백엔드 -> 데이터베이스 -> CI/CD -> 홈서버 운영까지 직접 수행하는 end-to-end 포트폴리오 플랫폼
```

이 프로젝트는 단순 landing page가 아니다. 실제로 내가 쓰고, 지인들이 쓸 수 있는 서비스를 하나씩 올리는 장기 운영 플랫폼이다.

## StablePay와의 관계

기존 프로젝트:

```text
/Users/banghobae/Documents/2030-korea-stablepay/2030-korea-stablepay-network
```

StablePay는 Go 기반 결제/원장/정산 기준 구현이다.

NaruWorks에서는 StablePay를 아래 중 하나로 연결한다.

```text
1. 외부 payment service처럼 API로 연동
2. stablepay-adapter service 작성
3. 나중에 Spring Boot payment module로 재구현
```

현재 판단:

```text
StablePay를 NaruWorks 안에 바로 합치지 않는다.
먼저 독립 결제 도메인 기준 구현으로 유지한다.
NaruWorks는 플랫폼/운영/서비스 허브 역할을 맡는다.
```

## 아키텍처 원칙

1. 처음부터 거대한 플랫폼을 만들지 않는다.
2. 실제로 배포 가능한 작은 vertical slice를 먼저 만든다.
3. 서비스 기능과 운영 기능을 함께 포트폴리오로 남긴다.
4. StablePay는 결제/원장/정산 모듈로 분리한다.
5. 홈서버 운영은 보안, 백업, 로그, 재배포 가능성을 기준으로 설계한다.
6. 문서는 새 대화에서도 이어받을 수 있게 항상 현재 상태를 기록한다.

## Backend 코딩 컨벤션

초기 backend는 Gradle 멀티 모듈 구조를 기준으로 한다.

```text
naru-api
= Spring Boot 실행 애플리케이션, Controller, Request/Response DTO, API 예외 처리

naru-core
= Service, 트랜잭션 흐름, 도메인 객체 조합, repository/adapter 호출

naru-domain
= 핵심 도메인 model, enum type, 필요 시 value object

naru-infrastructure
= JPA, PostgreSQL repository 구현, 외부 API adapter, StablePay adapter
```

의존성 방향은 아래를 기본으로 한다.

```text
naru-api -> naru-core -> naru-domain
naru-infrastructure -> naru-core, naru-domain
```

Request/Response는 API DTO로 부르고 Java record를 우선 사용한다.

```text
ProjectResponse, CreateProjectRequest 같은 이름을 사용한다.
DTO 변환 메서드는 다른 객체에서 변환할 때 from(...), 값으로 생성할 때 of(...)를 사용한다.
```

Lombok은 초기부터 사용한다.

```text
Controller, Service 등 Spring bean의 생성자 주입은 @RequiredArgsConstructor를 우선 사용한다.
DTO와 단순 값 객체는 Lombok class보다 Java record를 우선 사용한다.
JPA Entity는 도입 시점부터 Lombok을 적용하되, 무분별한 @Data 사용은 피한다.
JPA Entity에는 setter를 만들지 않는다.
JPA Entity 필드에는 해당 필드가 무엇을 의미하는지 주석을 작성한다.
DB 테이블/컬럼 의미는 Flyway migration의 COMMENT ON TABLE/COLUMN으로 남긴다.
```

VO는 API Request/Response가 아니라 도메인 Value Object를 뜻한다.

```text
예: ProjectSlug, Email, Money
```

## 초기 Phase

```text
Phase 1: Platform Core
목표: NaruWorks 사이트, 관리자 기본 구조, 프로젝트/서비스 허브

Phase 2: Home Server Ops
목표: Docker Compose, Caddy, HTTPS, CI/CD, 백업, 로그, health check

Phase 3: StablePay Integration
목표: 서비스별 결제 요청, 크레딧/포인트, ledger, settlement, admin 정산 화면

Phase 4: Real Services
목표: 지인 또는 내가 실제로 사용하는 작은 서비스를 추가하고 운영한다.
```
