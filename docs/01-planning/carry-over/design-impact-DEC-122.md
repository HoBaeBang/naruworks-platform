# DEC-122 업로드 화면 영향

- 날짜: 2026-11-27 (Asia/Seoul)
- 대상: [DEC-122](../02-decision-log/decision-log.md), FR-DRV-003, UF-03
- 상태: 라운드 20(DEC-122) 개정분은 호배님 승인 대기. 화면 동작은 라운드 22의 DEC-128에 반영했으며 해당 개정분은 호배님 승인 대기.
- 목적: 진행률, 실패 후 재시도, 재개, 취소, 크기 초과 안내에 적용할 기존 규칙과 라운드 22에서 정한 화면 동작을 정리한다.

기본은 DEC-090에 따라 파일을 한 번에 올리고, 도중에 끊기면 처음부터 다시 올린다. DEC-122는 1GB(1,073,741,824바이트) 단일 업로드가 Cloudflare 요청 본문 한도에 막힐 때만 분할 업로드를 허용한다. 요청 본문 한도는 [미확인]이며, 설정 확인 위치는 [CO-02](README.md)를 따른다.

## (i) 기존 DEC로 이미 정해진 것

| 항목 | 적용 | 규칙과 근거 |
|---|---|---|
| 실패 시 재시도 안내 | 기본 단일 업로드 | 끊긴 파일을 다시 올릴 때 전체를 처음부터 올린다(DEC-090). 개별 업로드 실패 이유를 안내하고 실패한 파일을 목록에 추가하지 않는 것은 FR-DRV-003에 명시돼 있다. |
| 재개 안내 | 기본 단일 업로드 | 끊긴 지점에서 이어 올리는 동작을 제공하지 않는다(DEC-090). |
| 크기 초과 안내 | 기본·분할 예외 공통 | 파일당 1GB는 1,073,741,824바이트이며, 이 크기까지 허용하고 1,073,741,825바이트부터 거부한다(DEC-037, DEC-086). 개별 파일의 초과 시 한도를 안내한다(FR-DRV-003). 분할 예외에도 같은 파일 한도를 적용한다(DEC-122). |
| 폴더 업로드와 0바이트 | 기본·분할 예외 공통 | 폴더에서는 1GB 초과 파일만 빼고 나머지를 올리며, 빠진 파일을 사용자에게 안내한다(DEC-106). 0바이트 파일은 개별 업로드와 폴더 업로드 모두에서 거부한다(DEC-107). |
| 총용량 | 기본·분할 예외 공통 | 1차에는 드라이브 총용량 제한을 두지 않는다(DEC-010). |

## (ii) 디자인·설계 재량에 맡길 것

| 항목 | 적용 | 재량 범위 |
|---|---|---|
| 진행률·실패·재개·취소 안내의 표현 | 기본·분할 예외 공통 | 상태 표시와 안내의 배치, 표시 요소, 문구를 설계한다. (iii)의 확정 동작을 따른다. |
| 크기 초과 안내 | 기본·분할 예외 공통 | 한도와 폴더에서 빠진 파일을 안내하는 규칙에 맞춰 문구와 표시 위치를 정한다. |
| 분할 업로드 구현 | DEC-122 예외 | 조각 크기, 구현에서의 재개 여부와 구현 방식은 DEC-122에 따라 설계에서 정한다. 화면에는 이어 올리기 동작을 두지 않는다(DEC-128). |

## (iii) 확정된 화면 동작(DEC-128)

단일 업로드와 분할 예외 모두 전송 중에는 업로드 중 상태만 표시하며, 파일 전체 기준 진행률은 표시하지 않는다. 전송 중에는 화면에서 취소할 수 있다. 실패하면 이유를 안내한 뒤 파일을 다시 선택해 처음부터 올리게 한다. 화면에서 끊긴 지점부터 이어 올리는 동작은 제공하지 않는다(DEC-128). [라운드 22](../01-interview/round-22.md) 답변(2026-11-27 21:20 KST, 카드 t35s379). 개정분은 승인 대기다. 아래에 선택지 이력을 남긴다.

| 항목 | 적용 | 질문과 선택지 이력 | 채택 |
|---|---|---|---|
| 업로드 진행률 표시 | 기본·분할 예외 각각 | 진행 중에 어디까지 올렸는지 보여 줄까? ① 업로드 중이라는 상태만 표시 ② 파일 전체 기준 진행률 표시. | ① (DEC-128) |
| 실패 시 재시도 안내 | 기본 단일 업로드 | 실패 이유와 함께 처음부터 다시 올리는 방법을 어떻게 제공할까? ① 안내 후 사용자가 파일을 다시 선택 ② 실패한 항목에 처음부터 다시 올리는 버튼 제공. 두 경우 모두 DEC-090을 따른다. | ① (DEC-128) |
| 실패 시 재시도 안내 | DEC-122 예외 | 이어 올리기가 불가능한 실패에서 처음부터 다시 올리는 방법을 어떻게 제공할까? ① 안내 후 사용자가 파일을 다시 선택 ② 실패한 항목에 처음부터 다시 올리는 버튼 제공. | ① (DEC-128) |
| 재개 안내 | DEC-122 예외 | 끊긴 업로드를 사용자가 어떻게 다시 시작할까? ① 파일 전체를 처음부터 다시 올리도록 안내 ② 설계에서 이어 올리기를 구현하고 재개할 수 있는 경우, 끊긴 지점부터 이어 올리는 동작을 화면에 안내하고 제공. 재개 여부와 방식은 DEC-122에서 설계에 맡겼으므로, 화면에서 재개를 제공하는 안은 설계 검토를 전제로 한다. | ① (DEC-128) |
| 취소 | 기본·분할 예외 각각 | 전송 중인 업로드를 화면에서 취소할 수 있게 할까? ① 취소 동작 제공 ② 취소 동작 생략. | ① (DEC-128) |
