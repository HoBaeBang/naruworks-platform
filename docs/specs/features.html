03 · Feature Design

NaruWorks 기능 설계

기능을 “화면에 보이는 것”, “backend가 보장하는 것”, “다음 단계로 미룬 것”으로 나눠 관리합니다. 완료 표시는 실제 동작 가능한 범위를 뜻하며, 장기 아이디어와 구분합니다.

플랫폼과 회원

완료

초대 기반 Google 가입

초대 링크 또는 코드→Google 로그인→약관 동의→USER + APPROVED 생성

신규 회원은 유효한 추천 코드가 있어야 로그인할 수 있습니다. OAuth 성공만으로는 Member를 만들지 않고, 약관 동의 성공 시점에 추천인 관계와 함께 생성합니다. 기존 회원은 상태별 화면으로 즉시 이동합니다.

완료

관리자 회원 관리

ADMIN은 회원과 추천인 관계를 보고 일반 회원을 정지·복구할 수 있습니다. 관리 기능은 플랫폼 목적이 아니라 서비스 운영에 필요한 최소 범위로 유지합니다.

Naru Calendar

완료

개인 일정 CRUD와 소유권

회원은 자기 일정만 조회·생성·수정·삭제할 수 있습니다. 일정은 제목, 설명, 시간, 종일 여부, 장소, 색상을 가집니다. 종일 일정은 색을 채워 표시하고 시간 일정은 테두리·시간·제목을 구분해 표시합니다.

완료

반복·음력·날짜 메타데이터

WEEKLY, MONTHLY, YEARLY, LUNAR_YEARLY 반복은 원본 한 건을 저장하고 화면 조회 기간에만 발생 회차를 계산합니다. 한국 공휴일·음력은 사용자 일정과 별도의 읽기 전용 날짜 메타데이터입니다.

완료

연간·월간·주간·일간 보기

모든 보기는 같은 일정 조회 API와 날짜 메타데이터 API를 공유합니다. 일요일/공휴일은 빨간색, 토요일은 파란색 계열로 표시합니다.

Google Calendar

완료

읽기 권한 연결

Calendar의 연결 버튼→Google 동의→state 검증→암호화 refresh token 저장

기존 NaruWorks 로그인 OAuth와 별도 클라이언트로 권한을 연결합니다. Calendar 화면은 연결한 이메일과 상태를 표시합니다.

완료

선택한 Google Calendar의 읽기 전용 가져오기

조회 기간에 선택 캘린더의 단일 발생 일정을 읽어 external_calendar_events에 저장하고 Naru 일정과 병합합니다. 외부 일정은 source=GOOGLE, readOnly=true로 반환되어 상세 확인만 가능합니다.

다음

증분 동기화

nextSyncToken으로 변경된 일정만 조회하고 삭제 이벤트·토큰 만료·실패 재시도 정책을 추가합니다.

보류

Google Calendar로 보내기와 양방향 동기화

현재 목표가 아닙니다. 수정 충돌, 삭제 전파, 반복 일정 원본/회차 매핑, 동기화 기준 시각을 별도로 설계한 뒤 검토합니다.

다음 설계 우선순위

순서기능먼저 결정할 것
1Google Calendar 목록·선택회원당 선택 가능한 캘린더 수, 기본 캘린더 정책
2외부 이벤트 가져오기all-day/time 변환, 반복 인스턴스 식별자, 읽기 전용 표현
3증분 동기화nextSyncToken 만료·삭제 이벤트·실패 재시도
4Naru Drive파일 소유권, 저장소, 공유 범위, 백업 정책
