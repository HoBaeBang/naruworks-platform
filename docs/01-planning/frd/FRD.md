## 4. AUTH — 통합 로그인·로그아웃·가입·탈퇴, 계정 설정

### FR-AUTH-001 Google 통합 로그인으로 가입·로그인하고 즉시 사용

- **설명**: Google 소셜 로그인 하나로 NaruWorks에 가입하거나 로그인한다. 이 통합 로그인은 이후 연동하는 모든 오픈소스의 공통 인증 기반이다. 신규 가입자는 관리자 승인 없이 바로 서비스를 사용할 수 있다. 1차에는 Google만 지원한다(DEC-001, DEC-005, DEC-007).
- **상위 REQ**: REQ-001, REQ-002, REQ-003
- **관련 BR**: BR-001, BR-002, BR-003
- **사용자/권한**: 비회원(가입), 기존 회원(로그인). 정지된 회원은 FR-AUTH-005를 따른다. 탈퇴 후 보관 기간 안의 재가입은 FR-AUTH-004를 따른다.
- **입력·처리·결과**: 사용자가 Google 로그인을 선택한다. Google 계정 인증에 성공하면, 처음 온 사용자는 회원으로 등록되고 곧바로 이용을 시작한다. 이미 회원인 경우 로그인되어 서비스 목록 홈(FR-HOME-001)으로 이동한다. Google 외 소셜 로그인 수단은 보여 주지 않는다. 로그인 화면에서도 화면 언어(한국어·영어)를 바꿀 수 있다(DEC-100). 로그인 전에 고른 언어와 계정 언어가 다르면 로그인 후 계정 언어를 따른다(DEC-110). 로그인하지 않은 사용자가 로그인이 필요한 주소에 바로 들어오면 로그인 화면으로 이동하고, 로그인에 성공하면 원래 주소로 돌아간다. 링크 보기에서 로그인한 경우에도 원래 링크로 돌아간다(DEC-118).
- **예외·빈 상태**: Google 인증을 취소하거나 실패하면 가입·로그인은 완료되지 않고, 사용자는 인증 전 화면에서 다시 시도할 수 있다. 정지된 계정의 다음 로그인은 차단된다(BR-005). 이미 로그인한 사용자가 로그인 화면 주소에 접근하면 홈(WF-02)으로 이동한다(DEC-119).
- **화면 필요 여부**: 예 (WF-01 로그인. 언어 전환 UI 반영은 T-03에서 확인한다(DEC-100). 일반 로그인 성공 후에는 WF-02 서비스 목록 홈으로, 주소 복귀가 필요한 경우에는 원래 주소로 이동한다(DEC-118). UF-01)
- **MoSCoW**: Must

### FR-AUTH-002 통합 로그아웃

- **설명**: 사용자가 NaruWorks에서 로그아웃하면 연동 오픈소스(1차: Litpage)까지 한 번에 로그아웃된다(DEC-015). 로그아웃은 지금 쓰는 기기에만 적용하며, 통합 로그아웃은 그 기기의 나루·Litpage 세션을 함께 끝낸다. 같은 회원이 다른 기기에서 연 세션은 끊지 않는다(DEC-094).
- **상위 REQ**: REQ-004
- **관련 BR**: BR-004
- **사용자/권한**: 로그인한 회원. 조작은 공통 헤더의 회원 메뉴에서 한다(FR-SHELL-001).
- **입력·처리·결과**: 사용자가 로그아웃을 선택하면 나루와 연동 오픈소스 이용이 함께 종료되고, 로그인 전 화면으로 돌아간다.
- **예외·빈 상태**: 이미 로그아웃된 상태에서 다시 로그아웃을 요청하면 추가 처리 없이 로그인 전 상태를 유지한다.
- **화면 필요 여부**: 화면 없음 (종료 후 로그인 화면 WF-01로 이동. UF-01)
- **MoSCoW**: Must

### FR-AUTH-003 회원 탈퇴

- **설명**: 회원이 스스로 이용을 종료할 수 있다. 탈퇴 후 데이터는 30일 보관되고, 그 기간이 지나면 삭제된다. 탈퇴 메뉴는 프로필과 별도인 계정 설정 화면(FR-AUTH-006, DEC-050)에 두며, 계정 설정은 프로필 화면 안의 링크로 들어간다(DEC-055).
- **상위 REQ**: REQ-026
- **관련 BR**: BR-007, BR-027
- **사용자/권한**: 로그인한 일반 회원(본인 계정만). 관리자 정지는 이 기능이 아니다(FR-ADM-002).

## 7. OSS — Litpage 연동·저장 폴더

### FR-OSS-002 서비스별 저장 폴더 선택·변경

- **설명**: 사용자가 각 오픈소스 서비스에 처음 들어갈 때, 결과물을 저장할 나루 드라이브 폴더를 고른다. 기본값은 서비스 이름 폴더이다(예: Litpage는 /litpage 아래). 이후 저장 폴더를 바꿀 수 있으며, 바꾸면 이후 결과물만 새 폴더에 저장하고 기존 결과물은 옮기지 않는다(DEC-032).

- **관련 BR**: BR-011

- **입력·처리·결과**: 첫 진입 시 저장 위치 선택 화면을 보여 주고, 기본값으로 서비스 이름 폴더를 제시한다. 사용자가 기본값을 그대로 쓰거나 다른 폴더를 고르면 그 위치를 이후 자동 저장(FR-OSS-003)에 사용한다. 기본 폴더가 없으면 만들어 쓸 수 있게 한다. 이후 저장 폴더를 바꾸면 그때부터의 결과물만 새 폴더에 저장되고, 이미 저장된 결과물은 원래 자리에 남는다. 이후 저장 폴더를 바꿀 때는 처음 진입 때와 같은 저장 폴더 선택 화면을 다시 쓴다(DEC-063).

- **관련 BR**: BR-011
- **사용자/권한**: 해당 오픈소스를 사용하는 회원.

- **예외·빈 상태**: 저장에 실패하면 사용자에게 실패를 알리고, 작업 내용을 잃지 않도록 안내한다.

## 8. DRV — 나루 드라이브

### FR-DRV-001 나루 드라이브 화면

- **설명**: 1차 범위에 나루 드라이브 화면을 둔다. 사용자는 저장된 결과물과 올린 파일을 한곳에서 본다. 1차에는 드라이브 총용량 제한을 두지 않는다(BR-010). 파일 하나 업로드 한도는 1GB(1,073,741,824바이트)다(BR-024, DEC-037, DEC-086). 사용한 용량의 표시는 프로필 화면(FR-SHELL-003)에서 하며, 총용량 한도는 두지 않고 표시하지도 않는다(BR-010, DEC-010, DEC-047).
- **상위 REQ**: REQ-010, REQ-017
- **관련 BR**: BR-010, BR-018, BR-024
- **사용자/권한**: 로그인한 회원(본인 드라이브). 공유받은 항목은 FR-DRV-006을 따른다.
- **입력·처리·결과**: 홈이나 서비스 전환에서 드라이브에 들어가면 폴더·파일 목록을 보여 준다. 여기서 폴더 관리, 올리기·내려받기, 삭제, 공유, 미리보기, Litpage 문서 열기를 시작한다. 휴지통 화면은 나루 드라이브 왼쪽 메뉴에서 들어간다(DEC-064, FR-DRV-004). 폴더·파일 목록의 열은 이름, 종류, 크기, 수정일, 공유 여부이다(DEC-075). 종류는 폴더와 파일을 구분하고, 파일은 형식과 Litpage 문서 여부를 나타낸다. 드라이브와 휴지통은 1차에 항목을 하나씩 조작하며 다중 선택을 제공하지 않는다(DEC-116).
- **예외·빈 상태**: 파일이 하나도 없으면 빈 상태를 보여 주고, 폴더를 만들거나 파일을 올릴 수 있음을 안내한다. 총용량 초과 안내는 1차에 두지 않는다. 파일당 1GB를 넘는 올리기는 FR-DRV-003을 따른다.
- **화면 필요 여부**: 예 (WF-05 나루 드라이브. UF-03)
- **MoSCoW**: Must

### FR-DRV-002 폴더 생성·이름 변경·이동

- **설명**: 드라이브에서 폴더를 만들고, 이름을 바꾸고, 다른 위치로 옮길 수 있다(DEC-011).

### FR-DRV-003 파일·폴더 업로드·다운로드

- **설명**: 드라이브에서 파일을 올리거나 내려받을 수 있다. 폴더를 통째로 올리는 업로드도 1차에 포함한다(DEC-086). 드라이브 총용량 제한은 두지 않으나(BR-010, REQ-017), 파일 하나의 업로드 최대 크기는 1GB, 즉 1,073,741,824바이트다. 이 크기까지 허용하고 초과는 거부한다(BR-024, DEC-037, DEC-086).
- **상위 REQ**: REQ-012, REQ-017
- **관련 BR**: BR-010, BR-018, BR-022, BR-024
- **사용자/권한**: 본인 드라이브에 올리는 회원, 본인 파일 또는 내려받을 수 있는 파일을 받는 회원. 회원 보기 공유와 비회원 링크의 다운로드 허용은 공유자가 선택한다(BR-022, DEC-031, DEC-035).
- **입력·처리·결과**: 사용자가 파일을 선택해 올리면 현재 폴더에 저장되고 목록에 나타난다. 사용자가 폴더를 선택해 올리면, 그 폴더가 현재 폴더 아래에 업로드 이름 충돌 규칙을 적용한 이름과 기존 하위 구조로 만들어지고 안의 파일이 올라간다. 폴더 안의 파일 하나하나에 파일 한도(1,073,741,824바이트)를 적용하며, 한도를 넘는 파일만 빼고 나머지 파일은 올리고, 빠진 파일은 사용자에게 안내한다(DEC-106). 기본은 한 번에 올리며, 분할 업로드와 이어 올리기는 두지 않고 끊기면 처음부터 다시 올린다(DEC-090). Cloudflare 요청 본문 한도에 대한 예외는 아래 DEC-122를 따른다. 내려받기를 선택하면 해당 파일을 받는다. 보기 공유·링크로 받은 파일의 내려받기는 공유자가 허용한 경우에 가능하며, 소유자 탈퇴 후 보관 중에는 차단한다(DEC-111). 폴더를 통째로 내려받는 기능은 이 FR에 포함하지 않는다.
- **예외·빈 상태**: 개별 파일 업로드가 실패하면 이유를 안내하고 그 파일을 목록에 추가하지 않는다. 빈 폴더에서도 올리기를 할 수 있다. 파일 크기가 1,073,741,824바이트를 넘으면(1,073,741,825바이트부터) 그 파일은 올리지 않고, 한도를 안내한다. 정확히 1,073,741,824바이트인 파일은 올린다. 드라이브 총용량 초과로는 거부하지 않는다(BR-010). 0바이트 파일은 개별 업로드와 폴더 업로드 모두에서 올리지 않는다(DEC-107). 폴더 업로드 중 한도를 넘는 파일이 있어도 전체를 멈추지 않는다(DEC-106, Q-083 해소). 기본 동작에서는 업로드가 끊기면 이어 올리지 않고 처음부터 다시 올리며, 끊긴 파일은 목록에 남지 않는다(DEC-090). 1GB(1,073,741,824바이트) 단일 업로드가 Cloudflare 요청 본문 한도에 막히는 경우에만 분할 업로드를 허용한다(DEC-122). 이때 조각 크기, 이어 올리기 여부, 구현 방식은 설계에서 정한다. 업로드 대상 위치에 같은 이름의 폴더·파일이 있으면 이름 뒤에 (1)을 붙인다. (1)이 있으면 (2), (3) 순으로 비어 있는 번호를 쓴다. 폴더 업로드에도 적용한다(DEC-108).
- **화면 필요 여부**: 예 (WF-05 나루 드라이브. 전용 화면은 없다. UF-03)
- **MoSCoW**: Must

### FR-DRV-004 삭제와 휴지통(30일 후 자동 삭제)

- **설명**: 드라이브에서 항목을 삭제하면 휴지통으로 들어간다. 사용자는 휴지통을 볼 수 있고, 휴지통의 파일은 30일 후 자동 삭제된다. 30일이 지나기 전에 휴지통에서 되돌릴 수 있다.
- **상위 REQ**: REQ-013
- **관련 BR**: BR-006, BR-018
- **사용자/권한**: 본인 드라이브의 소유자.
- **입력·처리·결과**: 사용자가 파일이나 폴더를 삭제하면 휴지통으로 옮긴다. 휴지통 화면은 나루 드라이브 왼쪽 메뉴에서 들어가며, 드라이브 화면의 휴지통 버튼으로 두지 않는다(DEC-064). 휴지통 화면에서 항목을 확인하고, 자동 삭제 전에 원래 위치로 되돌릴 수 있다. 휴지통에 들어간 지 30일이 지난 항목은 자동으로 완전히 삭제된다. 30일은 달력 날짜 기준으로 세며, 소유자가 탈퇴해 데이터가 보관 중인 동안에도 휴지통의 30일 시계는 계속 간다(DEC-096). [미확인] 달력 기준의 시간대·경계 시각은 정해지지 않았다(Q-085). 휴지통 목록의 열은 이름, 종류, 크기, 자동 삭제까지 남은 기간, 원래 위치이다(DEC-075). 수정일은 휴지통 목록에 두지 않는다. 드라이브와 휴지통은 1차에 항목을 하나씩 조작하며 다중 선택을 제공하지 않는다(DEC-116).
- **예외·빈 상태**: 휴지통이 비어 있으면 빈 상태를 보여 준다. 이미 30일이 지나 삭제된 항목은 되돌릴 수 없다. 휴지통에 있는 파일의 공유 링크는 막히고, 복원하면 다시 열린다(BR-006, DEC-030). 30일 후 자동 삭제되면 대상 파일이 없으므로 링크는 열 수 없다.
- **화면 필요 여부**: 예 (삭제는 WF-05 나루 드라이브, 휴지통 화면은 WF-06 휴지통. UF-03)
- **MoSCoW**: Must

참고: 휴지통에서 되돌리기는 「휴지통을 제공한다」는 요구의 기본 동작으로 둔다. 별도의 보관 기간 예외는 DEC-019(30일 후 자동 삭제)를 따른다.

### FR-DRV-005 Litpage 문서를 누르면 Litpage로 열기

- **설명**: 드라이브 목록에서 Litpage 문서를 누르면 Litpage로 열어 이어서 작업할 수 있다.
- **상위 REQ**: REQ-014
- **관련 BR**: BR-013, BR-018, BR-019
- **사용자/권한**: 해당 문서에 접근할 수 있는 회원. Litpage가 숨김이면 오픈소스 사용은 차단된다(BR-013, DEC-028).
- **입력·처리·결과**: 사용자가 드라이브에서 Litpage 문서를 선택하면 Litpage 화면으로 이동하고, 그 문서가 열린다. 공통 헤더·푸터는 그대로 유지된다(FR-SHELL-001, FR-SHELL-002).
- **예외·빈 상태**: 문서를 열 수 없으면 실패를 안내하고 드라이브에 남는다. Litpage가 숨김이면 드라이브에서 결과 파일은 볼 수 있으나, Litpage로 열어 사용하지는 못한다(BR-013, DEC-028).
- **화면 필요 여부**: 예 (WF-05 나루 드라이브에서 고르고, WF-04 Litpage로 연다. UF-03)
- **MoSCoW**: Must

### FR-DRV-006 회원 공유(보기/편집 권한 선택, 보기 시 다운로드 선택)

- **설명**: 드라이브 파일을 나루 회원에게 공유할 수 있다. 공유할 때 사용자가 보기 권한과 편집 권한 중 하나를 선택한다. 보기 권한으로 공유할 때는 다운로드 허용 여부를 공유하는 사람이 선택한다(BR-022, DEC-031). 대상 회원은 이메일로만 검색하며, 검색은 전체 이메일 완전 일치(대소문자 무시)이고 활동 회원만 찾는다(DEC-058, DEC-061).
- **상위 REQ**: REQ-015
- **관련 BR**: BR-007, BR-009, BR-014, BR-018, BR-022, BR-026
- **사용자/권한**: 공유를 거는 사람(파일 소유자). 공유받는 사람은 선택된 보기 또는 편집 권한과, 보기일 경우 공유자가 정한 다운로드 허용 범위만큼만 사용한다.
- **입력·처리·결과**: 소유자가 대상 회원을 전체 이메일 완전 일치(대소문자 무시)로만 찾아 권한(보기/편집)을 정해 공유한다. 표시 이름이나 이메일의 일부만으로는 검색하지 않으며, 활동 회원이 아니면 찾아지지 않는다(DEC-058, DEC-061). 보기 권한을 줄 때는 다운로드를 허용할지 끄거나 켠다. 보기 권한을 받은 회원은 파일을 볼 수 있고, 다운로드가 허용된 경우에만 내려받을 수 있다. 편집 권한을 받은 회원은 내용을 수정할 수 있다. 공유 파일을 동시에 편집해 충돌하면 원본이 있던 폴더에 '이름 (충돌 사본)'으로 저장하고, 버전은 최근 10개를 30일 보관한다(DEC-097, DEC-112). 다운로드를 금지한 회원 보기 공유와 비회원 보기 링크는 원본 파일을 보내지 않고 화면용으로만 보여 준다(DEC-095, DEC-109). 공유받은 파일은 공유받은 회원이 드라이브에서 찾을 수 있어야 한다. 검색된 대상과 이미 공유된 회원을 보일 때는 표시 이름을 쓰고, 표시 이름을 아직 정하지 않았으면 Google 계정 이름을 대신 보여 준다(BR-026, DEC-053, DEC-054). 공유를 마치거나 닫아도 회원 공유 화면을 떠나지 않고, 공유 중인 회원 목록만 갱신한다(DEC-065).
- **예외·빈 상태**: 해당 이메일의 활동 회원을 찾을 수 없거나 자기 자신에게만 공유하려는 경우 완료하지 않고 안내한다. 공유를 취소하면 해당 회원의 접근을 거둔다. 소유자가 탈퇴해도 30일 보관 기간 동안 공유는 유지되되, 이 기간에는 공유받은 사람이 그 파일을 보기만 할 수 있고 편집·다운로드할 수 없으며, 데이터가 삭제되면 공유가 끊긴다(BR-007, DEC-029, DEC-099, DEC-111). 공유받은 회원이 탈퇴하면 그 회원이 받은 공유는 탈퇴 즉시 끊긴다(DEC-099). 탈퇴로 끊긴 받은 공유는 재가입해도 복구하지 않는다(DEC-114).
- **화면 필요 여부**: 예 (WF-07 회원 공유. UF-03)
- **MoSCoW**: Must

### FR-DRV-007 비회원 링크 공유(보기만, 다운로드 선택, 만료·비밀번호 없음)

- **설명**: 드라이브 파일을 링크로 비회원에게도 공유할 수 있다. 링크를 받은 비회원은 보기만 할 수 있고 편집은 할 수 없다. 1차에는 링크 만료와 비밀번호를 두지 않는다. 다운로드 허용 여부는 공유하는 사람이 선택한다(BR-022, DEC-035).
- **상위 REQ**: REQ-015
- **관련 BR**: BR-006, BR-007, BR-008, BR-009, BR-014, BR-018, BR-022, BR-021
- **사용자/권한**: 링크를 만드는 사람(파일 소유자, 로그인한 회원). 링크를 연 사람은 비회원 또는 로그인하지 않은 사용자이며 보기만 가능하고, 내려받기는 공유자가 허용한 경우에만 가능하다.
- **입력·처리·결과**: 소유자가 링크 공유를 켜면 보기 전용 링크가 만들어지고, 그때 다운로드 허용을 켜거나 끈다. 생성된 주소를 표시하고 복사할 수 있게 한다(AC-FR-DRV-007-01). 링크를 연 사람은 만료나 비밀번호 없이 파일을 볼 수 있다. 편집은 할 수 없다. 공유자가 다운로드를 허용한 링크에서 내려받을 수 있으며, 탈퇴 보관 중에는 차단한다(DEC-111). 다운로드를 금지한 링크는 원본 파일을 보내지 않고 화면용으로만 보여 준다(DEC-095). 링크 보기 화면에는 공통 헤더와 공통 푸터를 둔다. 헤더에는 로그인 버튼이 있으며, 로그인 버튼과 로고, 카테고리(문서·저장소), 서비스 전환 메뉴를 누르면 모두 로그인 화면으로 이동한다(DEC-071, DEC-076, DEC-070, FR-SHELL-001, FR-SHELL-002). 링크 보기에서 로그인에 성공하면 원래 링크로 복귀한다(DEC-118).
- **예외·빈 상태**: 소유자가 링크 공유를 끄면 기존 링크로 더 이상 볼 수 없다. 파일이 휴지통에 있으면 링크는 막히고, 복원하면 다시 열린다(BR-006, DEC-030). 자동 삭제 후에는 파일이 없어 링크를 열 수 없다. 소유자가 탈퇴해도 30일 보관 기간 동안 링크는 보기 전용으로 유지되며 다운로드는 차단한다. 데이터가 삭제되면 링크가 끊긴다(BR-007, DEC-029, DEC-099, DEC-111). 비회원이 링크 꺼짐, 휴지통, 삭제, 탈퇴로 인해 링크를 열 수 없으면 이유에 관계없이 같은 안내를 보여 준다(DEC-117).
- **화면 필요 여부**: 예 (링크 보기 화면은 WF-08. 링크를 만드는 전용 WF는 없고, 드라이브에서 시작한다. UF-04)
- **MoSCoW**: Must

### FR-DRV-008 썸네일 미리보기·파일 형식 아이콘

- **설명**: 드라이브에서 파일을 미리볼 수 있다. 1차 수준은 대표 썸네일(이미지 축소본, PDF 첫 페이지, 동영상 첫 장면 등)을 마우스를 올렸을 때 보여주는 정도이다. 모든 파일 형식을 대상으로 하되, 썸네일을 만들 수 없는 파일은 파일 형식 아이콘으로 표시한다(DEC-018, DEC-022).
- **상위 REQ**: REQ-016
- **관련 BR**: BR-012, BR-018
- **사용자/권한**: 해당 파일을 볼 수 있는 회원. 비회원 링크 보기 화면에서도 보기 권한 범위 안의 미리보기를 적용할 수 있다.
- **입력·처리·결과**: 마우스를 쓰는 기기에서는 목록에서 파일에 마우스를 올리면, 가능한 경우 대표 썸네일을 보여 주고, 불가능한 경우 파일 형식 아이콘을 보여 준다. 터치 기기에서는 마우스 올림 썸네일 미리보기를 생략한다(DEC-084). 터치 기기에서 썸네일 대신 다른 미리보기 수단(예: 탭으로 보기)을 둘지는 1차에 정하지 않는다.
- **예외·빈 상태**: 썸네일을 아직 준비 중이면 잠시 아이콘이나 대기 표시를 쓸 수 있으며, 최종적으로 만들 수 없으면 파일 형식 아이콘으로 둔다. 터치 기기에서는 썸네일 미리보기가 나타나지 않는 것이 정상이며, 오류로 안내하지 않는다. [미확인] 터치 기기를 가르는 기준(기기 종류, 입력 방식 등)과 터치 기기의 목록에서 파일 형식 아이콘을 항상 보일지는 정해지지 않았다.
- **화면 필요 여부**: 예 (WF-05 나루 드라이브. 전용 미리보기 화면은 없다. UF-03)
- **MoSCoW**: Must

### FR-ADM-001 회원 목록 조회

- **설명**: 관리자는 회원 목록을 조회할 수 있다.
- **상위 REQ**: REQ-018
- **관련 BR**: BR-017, BR-026
- **사용자/권한**: 미리 지정한 관리자 계정만 이 기능을 쓴다. 화면에서 관리자 권한을 부여하거나 회수하지 않는다(BR-017, DEC-033).
- **입력·처리·결과**: 관리자는 공통 헤더 회원 메뉴의 '관리'(관리자에게만 보임, DEC-067, FR-SHELL-001)로 관리 화면에 들어간 뒤, 회원 목록을 열어 회원들을 볼 수 있다. 정지 여부 등 관리에 필요한 상태를 구분해 보여 준다. 회원 목록의 열은 표시 이름, 이메일, 정지 여부이다(DEC-075). 표시 이름을 아직 정하지 않은 회원은 Google 계정 이름을 대신 보여 준다(BR-026, DEC-053, DEC-054). 가입일은 두지 않는다. 관리자 회원 목록에는 페이지 나눔만 제공한다. 검색·정렬은 1차에 포함하지 않는다(DEC-121).
- **예외·빈 상태**: 회원이 없으면 빈 목록을 보여 준다. 일반 회원이 관리 화면 URL로 직접 들어오면, 안내 없이 서비스 목록 홈으로 보낸다(DEC-074). 관리자 권한이 없는 사용자는 이 기능에 들어갈 수 없다.
- **화면 필요 여부**: 예 (WF-11 관리로 들어간 뒤 WF-12 관리자 회원 목록. 일반 회원이 관리 URL로 직접 오면 WF-02로 보낸다. UF-06)
- **MoSCoW**: Must

### FR-ADM-002 회원 정지·해제

- **설명**: 관리자는 회원을 정지하거나 해제할 수 있다. 정지하면 재로그인·토큰 갱신·Litpage 진입이 새 로그인으로 보아 차단되며, 이미 로그인한 세션을 즉시 종료하지는 않는다(DEC-014, DEC-098. "로그아웃할 때까지 그대로 사용"이라는 DEC-027 문구는 DEC-098로 정정). 정지·해제는 감사 기록으로 남긴다(DEC-104).
- **상위 REQ**: REQ-019, REQ-020
- **관련 BR**: BR-005, BR-017
- **사용자/권한**: 미리 지정한 관리자 계정. 화면에서 관리자 권한을 부여·회수하지 않는다(BR-017, DEC-033). 일반 회원은 다른 회원을 정지할 수 없다.
- **입력·처리·결과**: 관리자가 회원 목록에서 대상을 골라 정지를 요청하면, 확인 대화상자에서 확인한 뒤에만 정지가 실행되고, 그 회원은 다음 로그인부터 차단된다(FR-AUTH-005, DEC-068). 대화상자에서 취소하면 정지하지 않고 회원 목록에 머문다. 이미 열린 세션은 즉시 끊기지 않지만, 토큰 갱신과 Litpage 진입은 차단된다(DEC-098, FR-AUTH-005). 관리자가 회원 목록에서 해제하면 다시 로그인하여 사용할 수 있다. 탈퇴 후 재가입한 정지 회원도 같은 절차를 따른다(DEC-114). 정지와 해제를 실행하면 그 동작이 감사 기록으로 남는다(DEC-104). [미확인] 기록 항목과 보관 기간은 정해지지 않았다(Q-091).
- **예외·빈 상태**: 이미 정지된 회원을 다시 정지해도 상태는 정지이다. 이미 이용 중인 회원을 해제하면 변화 없이 이용 중 상태를 유지한다.
- **화면 필요 여부**: 예 (WF-12 관리자 회원 목록. 정지 확인 대화상자는 전용 WF가 없다. UF-06)
- **MoSCoW**: Must

### FR-ADM-003 오픈소스 노출·숨김

- **설명**: 관리자는 오픈소스 서비스를 사용자에게 보이게 하거나 숨길 수 있다. 숨기면 모든 회원에게 숨기고 사용도 차단하며, 결과물은 나루 드라이브에만 남는다(BR-013, DEC-028).
- **상위 REQ**: REQ-021
- **관련 BR**: BR-013, BR-017
- **사용자/권한**: 미리 지정한 관리자 계정. 화면에서 관리자 권한을 부여·회수하지 않는다(BR-017, DEC-033).
- **입력·처리·결과**: 관리자가 오픈소스를 노출하면 쓸 수 있는 서비스 목록 등에 나타난다. 숨기면 모든 회원의 목록·카테고리·서비스 전환 메뉴에서 사라지고, 이미 사용 중이던 회원도 그 오픈소스를 쓸 수 없다. 기존 결과물은 드라이브에서 볼 수 있다. 1차 기본 오픈소스인 Litpage도 이 관리 대상에 포함될 수 있다. 오픈소스 목록의 열은 오픈소스 이름과 노출 상태(노출 또는 숨김)이다(DEC-075). 숨김·노출을 실행하면 그 동작이 감사 기록으로 남는다(DEC-104, Q-091).
- **예외·빈 상태**: 모든 오픈소스를 숨겨도 나루 드라이브 화면은 1차 직접 서비스로 유지된다.
- **화면 필요 여부**: 예 (WF-13 관리자 오픈소스 관리. UF-06)
- **MoSCoW**: Must

### FR-ADM-004 카테고리와 서비스 배정 관리

- **설명**: 관리자는 카테고리와 서비스 배정을 바꿀 수 있다. 카테고리 기본값은 문서·저장소이고, 초기 배정은 Litpage=문서, 나루 드라이브=저장소이다(BR-023, DEC-034, DEC-040). 변경은 서비스 목록 홈과 공통 헤더 카테고리에 바로 반영된다.
- **상위 REQ**: REQ-007
- **관련 BR**: BR-016, BR-017, BR-023
- **사용자/권한**: 미리 지정한 관리자 계정만 이 기능을 쓴다. 화면에서 관리자 권한을 부여하거나 회수하지 않는다(BR-017, DEC-033).
- **입력·처리·결과**: 처음에는 Litpage를 문서, 나루 드라이브를 저장소에 둔다. 관리자는 카테고리 목록에서 카테고리를 추가하거나 이름을 바꾸거나, 서비스가 배정되지 않은 카테고리를 삭제한다. 관리자는 각 서비스가 속할 카테고리를 바꾼다(DEC-068). 바꾸면 일반 회원의 홈·헤더 카테고리 분류가 그 내용으로 바뀐다. 숨긴 오픈소스는 배정과 관계없이 회원에게 보이지 않는다(BR-013). 서비스당 카테고리는 하나이며, 입력한 카테고리 이름을 그대로 표시한다(DEC-120). 카테고리에 배정된 서비스가 있으면 삭제를 막고 확인 대화상자를 띄운다(DEC-115).
- **예외·빈 상태**: 어떤 카테고리에도 노출된 서비스가 없으면 해당 카테고리는 빈 상태로 보인다. 초기 기본 배정은 Litpage=문서, 나루 드라이브=저장소이며, 이후 관리자가 바꿀 수 있다(BR-023, DEC-040).
- **화면 필요 여부**: 예 (WF-14 관리자 카테고리 관리. UF-06)
- **MoSCoW**: Must
