## 4. 구성 근거와 화면 일치 결과

- **WF-05 나루 드라이브:** 왼쪽 240열 서비스 표지·메뉴(`내 드라이브`·`휴지통`)와 오른쪽 848열 작업 영역, 선택 동작 띠, 목록 카드, 상태 A~E 배치 등 대부분 일치한다. 단, **데스크톱 호버 썸네일이 「행 옆」이 아니라 목록 `종류` 열 텍스트 위를 덮고 있는 점**이 문서와 모순된다(`major`). 또한 모바일 선택 동작 띠 대신 각 행 `더 보기(…)` 버튼만 두고 메뉴/시트는 미작도 상태다([screens.md](../../../docs/03-ui-design/screens/screens.md#L563) 한계에 명시).

- **WF-07 회원 공유:** 1120px 2단 카드(왼쪽 새로 공유 / 오른쪽 공유 중인 회원 3명), 제목 우측 「닫기」(모바일 X 아이콘 버튼), 상태 A·B 인라인 오류 및 「공유」 버튼 비활성 처리 모두 문서와 일치한다.

## 6. v4 시각 언어 일관성

- **헤더·드로어:** WF-05~07 데스크톱/모바일 헤더 및 드로어(닫기 X, 서비스 전환, 카테고리, 프로필, 로그아웃, 관리 없음, 테마 선택기 없음)가 v4와 일치한다. WF-08 데스크톱 비회원 헤더는 v4 규칙과 일치하나 모바일 햄버거 버튼은 불일치(`major`).
- **메달리온:** 서비스 표지(WF-05·06 왼쪽 패널)와 상태/영역 표지(WF-05 A, WF-06 A, WF-08 기본·A·B)에만 사용했고, 폼·목록·알림 안에는 쓰지 않았다.
- **알림 위치·오류 색:** 선택·목록 흐름을 끊지 않는 제목 아래 보조 줄 또는 필드 아래 인라인에 배치했고, 오류 아이콘은 `error` 토큰, 정보 아이콘은 `info` 토큰, 본문은 `text`를 사용했다.
- **금색 `accent`:** 메달리온 내부 수면선 한 줄에만 절제하여 사용했고 텍스트에는 쓰지 않았다.

## 7. 시각적 균형·공간 사용·위계·정렬·미감·사용성 요약

- **전반(데스크톱 1440 / 모바일 360):** v1의 좌측 좁은 열 쏠림 문제가 완전히 해소되었다. 모든 화면이 1120px 가운데 정렬 그리드 위에서 좌우 균형을 잡는다.
- **WF-05 (데스크톱 라이트 / 모바일 다크):** 서재(240) + 목록대(848) 2열 구성으로 1440 캔버스가 알차게 쓰인다. 위계(경로 → 제목·주 동작 → 선택 동작 띠 → 목록)가 명확하다. 모바일 다크에서는 분할 탭과 2줄 요약 목록이 깔끔하고 명도 대비도 높다. 다만 데스크톱 호버 썸네일이 `종류` 열을 덮은 점은 사용성·가독성 감점 요인이다.
- **WF-06 (데스크톱 라이트 / 모바일 다크):** WF-05와 동일한 틀을 유지해 학습 비용이 낮고, 정보 알림과 「원래 위치로 복원」 primary가 한눈에 들어온다. 모바일 다크에서도 행별 원래 위치와 남은 기간이 읽기 쉽다.
- **WF-07 (데스크톱 라이트 / 모바일 다크):** 1120px 2단 카드가 좌(입력·설정)에서 우(공유 중 목록)로 자연스럽게 읽힌다. 모바일 다크에서도 1열 적층과 터치 타겟 간격이 넉넉하고 정제된 SaaS 인상을 준다.
- **WF-08 (데스크톱 라이트 / 모바일 다크):** 기본·상태 A는 얇은 파일 정보 띠와 큰 보기 영역이 캔버스를 채워 균형이 좋다. 상태 B는 차단 카드 특성상 여백이 넓지만 중앙 메달리온과 2줄 안내가 정돈되어 있다. 모바일 다크의 하단 푸터와 보기 영역 구분도 명확하다.

## 8. 토큰·다크·모바일·대비 요약

- **토큰·아이콘:** Deep Ink 토큰(`primary` 라이트 `#1E3A5F` / 다크 `#8DB4F5` 등)과 커스텀 아이콘(`icons/*.svg` 기반 `ic/*`)만 사용했다. Grove Mint, Lucide 잔여, `secondary`/`accent` 텍스트 사용은 발견되지 않았다. 새 토큰·컴포넌트는 DS에 몰래 넣지 않고 [screens.md](../../../docs/03-ui-design/screens/screens.md#L539-L548)에 제안으로만 기록했다.
- **다크 모드:** 66장 전체에서 라이트 색 잔류, 저대비, `scrim`/`overlay` 누락 없이 라이트/다크 패리티가 유지되었다. (단, 다크 그림자는 DS 고정값 사용)
- **모바일:** `screens-wf05-08.figcraft` 검사 결과 모바일 버튼·탭·아이콘 버튼·컨트롤 모두 높이/너비 44px 이상이며 360px 폭에서 잘림·겹침이 없다.
- **대비 (DEC-102):** [design-system.md](../../../docs/03-ui-design/design-system/design-system.md#L208-L295)에서 이미 4.5:1 / 3:1 이상이 검증된 토큰 쌍(`text`/`surface-raised` 17.28:1 / 12.60:1, `text-muted`/`surface-raised` 7.44:1 / 6.07:1, `on-primary`/`primary` 11.50:1 / 8.90:1, `error`/`error-subtle` 5.70:1 / 4.88:1, `border-strong`/`surface-raised` 3.91:1 / 4.05:1 등)을 그대로 사용했으며, 시각적으로 실패로 보이는 쌍은 없다. 단, 화면별 실측은 수행하지 않아 `[미확인]`.

## 9. DEC-084·101 처리 결과

- **DEC-084 (터치 기기 마우스 올림 썸네일 생략):** 준수. 데스크톱 WF-05 기본에만 호버 썸네일 슬롯을 두었고, 모바일 WF-05 전체에서는 생략하고 파일 형식 아이콘만 표시했다.
- **DEC-101 (테마 선택기 위치 미정 Q-090):** 준수. 66개 프레임(헤더·모바일 드로어 포함) 어디에도 테마 선택기를 확정 배치하지 않았으며, 라이트/다크 프레임은 디자이너용 시안으로만 분리했다.

## 10. 검토하지 못한 부분과 그 이유

- **글꼴 렌더링(IBM Plex Sans KR):** 헤드리스 FigCraft 환경에 해당 글꼴이 없어 PNG가 대체 글꼴로 렌더링되었으므로, 실제 프로덕션 글꼴 기준의 정확한 줄바꿈·자간은 `[미확인]`.
- **호버·포커스·눌림·로딩 인터랙션 및 실제 기기 터치/스크린리더 읽기 순서:** 정적 시안 범위 밖이므로 `[미확인]`.
- **화면 단위 WCAG 대비 실측:** DS 토큰 대비표를 기준으로 확인했으며 개별 PNG 픽셀 단위 실측은 하지 않아 `[미확인]`.
- **66장 중 일부 반복 변형 PNG:** 주요 화면·상태·모드·드로어 위주로 다수 PNG를 직접 열람해 확인했으나, 모든 66장을 개별 열람하지는 못해 미열람 변형은 동일 구조 복제본으로 간주(`[미확인]`).
