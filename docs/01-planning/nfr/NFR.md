## 4. 상세

### 4.1 PERF — 성능·규모

#### NFR-PERF-001 1차 사용자 규모

- **내용**: 1차 예상 사용자는 지인 위주 100명 이내다. 성능·용량 목표는 이 규모를 전제로 한다.
- **적용 범위**: 전체
- **측정 기준**: 1차 운영에서 기대하는 사용자 수가 100명을 넘지 않는 규모인지를 전제로 검증한다. 동시 접속 목표는 NFR-PERF-004(DEC-049)를 따른다. 가입자가 80명, 100명에 도달하면 운영 경보를 내며 가입은 제한하지 않는다(NFR-PERF-004, DEC-088).
- **출처 DEC**: DEC-036 (동시 접속은 DEC-049, 경보는 DEC-088)

#### NFR-PERF-002 파일당 업로드 한도 1GB(1,073,741,824바이트)

- **내용**: 파일 하나의 업로드 최대 크기는 1GB, 즉 1,073,741,824바이트다. 이 크기까지 허용하고, 1,073,741,825바이트부터는 거부한다. 폴더를 통째로 올리는 업로드(1차 포함, DEC-086)에서도 폴더 안의 파일 하나하나에 같은 한도를 적용한다. 드라이브 총용량 제한은 1차에 두지 않는다. 폴더 업로드 중 한도를 넘는 파일이 있으면 그 파일만 빼고 나머지는 올리며, 빠진 파일은 사용자에게 안내한다(DEC-106). 기본은 한 번에 올리며, 분할 업로드와 이어 올리기는 두지 않고 끊기면 처음부터 다시 올린다(DEC-090). 1GB(1,073,741,824바이트) 단일 업로드가 Cloudflare 요청 본문 한도에 막히는 경우에만 분할 업로드를 허용한다(DEC-122). 이때 조각 크기, 이어 올리기 여부, 구현 방식은 설계에서 정한다. 0바이트 파일은 개별 업로드와 폴더 업로드 모두에서 거부한다(DEC-107).
- **적용 범위**: REQ-012, REQ-017, FR-DRV-003, BR-024, BR-010
- **측정 기준**: 1,073,741,824바이트 파일은 업로드할 수 있고, 1,073,741,825바이트 파일은 거부되며 한도가 안내된다. 폴더 업로드 안의 파일도 같은 기준으로 판정하며, 한도를 넘는 파일이 섞인 폴더를 올리면 그 파일만 올라가지 않고 나머지는 올라가며 빠진 파일이 안내된다. Cloudflare 요청 본문 한도에 막히지 않는 경우 한 번에 올리고, 전송이 끊기면 처음부터 다시 올리는지 확인한다(AC-FR-DRV-003-05). 한도로 1GB 단일 요청이 막히는 조건에서는 같은 크기의 파일을 분할해 업로드할 수 있는지 확인한다(AC-FR-DRV-003-09). 실제 Cloudflare 플랜의 요청 본문 한도는 [미확인]이다.
- **출처 DEC**: DEC-037, DEC-086, DEC-090, DEC-106 (총용량 없음은 DEC-010), DEC-107, DEC-122

#### NFR-PERF-003 응답 시간

- **내용**: 주요 화면 이동은 2초 이내, 썸네일 표시는 3초 이내에 끝나야 한다. 이 목표는 p95 기준이다. 즉 측정한 요청의 95%가 기준 시간 안에 끝나야 한다(DEC-087). 1GB 업로드처럼 파일 크기에 따라 달라지는 전송 시간은 이 목표에서 따로 본다. 썸네일 표시 목표는 마우스 올림 썸네일을 보여 주는 기기에 적용하며, 터치 기기는 썸네일 미리보기를 생략하므로(DEC-084) 대상이 아니다.
- **적용 범위**: 전체 (로그인, 홈, 드라이브, Litpage 진입, 썸네일 미리보기 등). 화면 이동 대상 FR: FR-AUTH-001, FR-HOME-001, FR-DRV-001, FR-OSS-001, FR-ADM-001, FR-DRV-007. 썸네일은 FR-DRV-008
- **측정 기준**: 동시 접속 20명(NFR-PERF-004, DEC-049), 사용자 규모 100명 이내(NFR-PERF-001, DEC-036) 전제에서, 화면 이동은 p95가 2초 이내, 썸네일 미리보기는 p95가 3초 이내인지 확인한다. 제외 구간: 파일 전송 시간, 썸네일 최초 생성 시간, Google 로그인 구간. 제외하지 않는 구간: Litpage 로딩 구간(Litpage 진입·화면 이동의 측정에 포함한다). [미확인] p95를 모으는 측정 기간·표본 수·측정 지점(브라우저 또는 서버)은 정해지지 않았다.
- **출처 DEC**: DEC-041, DEC-087, DEC-084 (규모 전제는 DEC-036, 동시 접속은 DEC-049)

#### NFR-PERF-004 동시 접속 20명

- **내용**: 1차 동시 접속 목표는 20명이다. 동시 접속은 최근 60초 안에 요청한 활성 세션의 수로 센다(DEC-088). 활성 세션이 20개일 때 오류율(5xx 응답과 타임아웃)은 0.1% 이하여야 한다. 가입자가 80명과 100명에 도달하면 운영 경보만 내며, 가입을 제한하지 않는다. 전체 사용자 규모 100명 이내(NFR-PERF-001, DEC-036)와 구분한다.
- **적용 범위**: 전체 (검증 대상 FR: FR-AUTH-001, FR-HOME-001, FR-DRV-001, FR-OSS-001, FR-ADM-001, FR-DRV-007)
- **측정 기준**: 활성 세션 20개(최근 60초 안에 요청한 세션)를 전제로 1차 주요 기능(로그인, 홈, 드라이브, Litpage, 관리자, 비회원 링크 보기)을 검증하고, 그 사이 오류율(5xx·타임아웃)이 0.1% 이하인지 확인한다. 가입자 수가 80명, 100명에 도달할 때 운영 경보가 나가는지 확인하고, 그때도 새 가입이 막히지 않는지 확인한다. [미확인] 오류율의 분모(요청 수 등)와 집계 창, 경보를 받는 사람·방법은 정해지지 않았다(설계 이관).
- **출처 DEC**: DEC-049, DEC-088

### 4.2 SEC — 보안·접근 통제

#### NFR-SEC-001 통합 로그아웃

- **내용**: 사용자가 NaruWorks에서 로그아웃하면 연동 오픈소스까지 한 번에 로그아웃되어야 한다. 세션이 나루에만 남거나 오픈소스에만 남는 상태가 되어서는 안 된다. 로그아웃은 지금 쓰는 기기에만 적용하며, 통합 로그아웃은 그 기기의 나루·Litpage 세션을 끝낸다. 같은 회원의 다른 기기 세션은 끊지 않는다(DEC-094).
- **적용 범위**: REQ-004, FR-AUTH-002, FR-OSS-001, BR-004
- **측정 기준**: 나루에서 로그아웃한 뒤, 같은 기기·같은 이용 흐름으로 연동 오픈소스에 다시 들어가지 못한다. 같은 회원이 다른 기기에서 연 세션은 그 로그아웃으로 끊기지 않는다.
- **출처 DEC**: DEC-015, DEC-094

#### NFR-SEC-002 회원 정지와 새 로그인 차단

- **내용**: 정지된 회원의 재로그인, 토큰 갱신, Litpage 진입은 모두 새 로그인으로 보아 차단한다(DEC-098). 이미 로그인한 세션을 즉시 종료하지는 않는다. "로그아웃할 때까지 그대로 사용"이라는 이전 문구(DEC-027)는 정정되어 더 이상 요구가 아니다. 정지 회원은 세션 만료 뒤 재로그인 때에도 차단된다(DEC-092). 정지된 회원이 탈퇴 후 재가입해도 정지는 유지된다(DEC-093). 정지 회원의 보관 데이터 복구와 관리자의 정지 해제는 DEC-114를 따른다.
- **적용 범위**: REQ-020, FR-AUTH-005, FR-ADM-002, FR-AUTH-004, FR-OSS-001, BR-005
- **측정 기준**: 정지 후 새로 로그인하면 차단되고, 정지 전에 열려 있던 세션이 토큰을 갱신하려 하면 거부되며, Litpage에 새로 들어가려 하면 차단된다. 정지 상태에서 탈퇴·재가입해도 정지가 유지된다. [미확인] 열린 세션이 갱신 때 차단되기까지의 최대 시간(토큰 갱신 주기)은 정해지지 않았다(Q-087, 설계 이관 성격).
- **출처 DEC**: DEC-014, DEC-092, DEC-093, DEC-098 (DEC-027은 DEC-098로 정정), DEC-114

#### NFR-SEC-003 보기 공유와 비회원 링크 접근

- **내용**: 비회원 링크는 보기만 가능하고, 1차에 만료와 비밀번호를 두지 않는다. 다운로드 허용 여부는 공유자가 선택한다. 편집은 할 수 없다. 다운로드를 금지한 회원 보기 공유와 비회원 보기 링크는 원본 파일을 보내지 않고 화면용으로만 보여 준다(DEC-095, DEC-109). 비회원이 링크 꺼짐, 휴지통, 삭제, 탈퇴로 인해 링크를 열 수 없으면 이유에 관계없이 같은 안내를 보여 준다(DEC-117).
- **적용 범위**: 회원 보기 공유(FR-DRV-006, BR-022), 비회원 보기 링크(FR-DRV-007, BR-008).
- **측정 기준**: 비회원 링크는 만료·비밀번호 입력 없이 볼 수 있고 편집할 수 없다. 다운로드를 금지한 회원 보기 공유와 링크 모두 원본 파일이 응답으로 전달되지 않고 화면용 표시만 된다. 열 수 없는 링크는 비회원에게 같은 안내로 표시된다. 화면용 형태는 설계 이관이다.
- **출처 DEC**: DEC-023, DEC-035, DEC-095, DEC-109, DEC-117

#### NFR-SEC-004 탈퇴 데이터 보관과 삭제

- **내용**: 탈퇴 회원의 데이터는 달력 날짜 기준 30일 보관 후 삭제하며, 보관 중에도 휴지통 시계는 계속 간다(DEC-096). 정지 회원도 같은 Google 계정으로 보관 기간 안에 재가입하면 보관 데이터를 복구한다. 탈퇴 시 끊긴 받은 공유는 재가입해도 복구하지 않는다. 정지는 유지되며 관리자가 회원 목록에서 해제한다(DEC-114). 보관 중 공유받은 사람은 보기만 할 수 있으며 편집·다운로드는 차단한다(DEC-099, DEC-111).
- **적용 범위**: REQ-026, FR-AUTH-003, FR-AUTH-004, FR-DRV-004, FR-DRV-006, FR-DRV-007, BR-007
- **측정 기준**: 같은 Google 계정으로 보관 기간 안에 재가입하면 정지 여부와 관계없이 보관 데이터가 복구된다. 받은 공유는 탈퇴 즉시 끊기고 재가입해도 복구되지 않는다. 보관 중에는 기존 공유의 편집·다운로드가 차단되며, 데이터 삭제 후에는 공유·링크도 열리지 않는다. [미확인] 달력 기준의 시간대·경계(Q-085).
- **출처 DEC**: DEC-021, DEC-029, DEC-096, DEC-099, DEC-111, DEC-114

#### NFR-SEC-005 비밀 값 미기재

- **내용**: 소셜 로그인 클라이언트 ID/시크릿 등 비밀 값은 설계·기획 문서에 적지 않는다. CO-03의 존재 위치(Google Cloud Console)만 참조한다. 도메인·Cloudflare(CO-01·CO-02)의 위치는 Cloudflare 대시보드이며 마찬가지로 값은 적지 않는다(`docs/01-planning/carry-over/README.md`).
- **적용 범위**: 전체 문서·산출물 (본 NFR, PRD, FRD, BR 포함)
- **측정 기준**: 문서에 비밀 값과 계정명이 없고, 필요 시 위치만 언급되어 있다.
- **출처 DEC**: DEC-082 (서비스 정의 v1.0·PRD 가정·제약 CO-03)

#### NFR-SEC-006 세션 수명

- **내용**: 로그인 세션은 유휴 7일, 최대 30일에 만료된다(DEC-092). 만료된 뒤에는 다시 로그인해야 하며, 정지된 회원은 이때 차단된다(NFR-SEC-002, DEC-098).
- **적용 범위**: FR-AUTH-001, FR-AUTH-002, FR-AUTH-005, BR-004, BR-005
- **측정 기준**: 7일 동안 아무 요청이 없던 세션은 만료되고, 계속 사용하더라도 로그인 시작 후 30일이 지나면 만료되어 다시 로그인하게 된다. [미확인] 유휴와 최대 기간을 재는 시각의 기준(서버·클라이언트)과 연동 오픈소스(Litpage) 세션에 같은 기간을 쓰는지는 정해지지 않았다(설계 이관).
- **출처 DEC**: DEC-092

### 4.3 AVAIL — 가용성

#### NFR-AVAIL-001 1차 가용률

- **내용**: 1차 서비스의 가용률 목표는 월 99%다. 지인 위주 100명 이내 규모를 전제로 한다. 미리 알린 점검 시간은 계산에서 제외하고, Google·Cloudflare 같은 외부 서비스 장애로 인한 중단도 제외한다(DEC-089). 출시 전에 가용률을 따로 검증하지 않으며, 출시 후 한 달 동안 관찰만 한다.
- **적용 범위**: 전체
- **측정 기준**: 출시 후 한 달 동안 서비스가 실제 이용 가능했던 비율이 99% 이상인지 관찰한다(한 달에 약 7시간 이내 중단). 미리 알린 점검 시간과 Google·Cloudflare 같은 외부 장애 시간은 중단으로 세지 않는다. 출시 전 부하·가용성 검증은 이 요구의 통과 조건이 아니다. [미확인] "미리 알린" 점검의 공지 시점·방법과, 외부 장애인지 가르는 판정 방법은 정해지지 않았다. 한 달 관찰 결과 목표에 못 미칠 때의 조치도 정해지지 않았다.
- **출처 DEC**: DEC-042, DEC-089 (규모 전제는 DEC-036)

### 4.4 USAB — 사용성

#### NFR-USAB-001 PC 웹과 반응형 모바일 웹

- **내용**: 1차 지원 환경은 PC 웹 브라우저와 모바일 웹(반응형)이다. 모바일 앱은 제공하지 않는다. 같은 기능을 작은 화면에서도 사용할 수 있어야 한다.
- **적용 범위**: 전체 화면 (로그인, 홈, 공통 헤더·푸터, 드라이브, Litpage 연동 화면, 관리자 화면, 비회원 링크 보기)
- **측정 기준**: PC 웹과 모바일 웹 브라우저에서 1차 기능을 수행할 수 있고, 별도 모바일 앱 설치 없이 동작한다. 공식 지원 브라우저 범위는 NFR-COMP-002를 따른다.
- **출처 DEC**: DEC-038

#### NFR-USAB-002 라이트·다크 모드

- **내용**: 프로필에서 시스템·밝게·어둡게 중 하나를 고른다. 선택은 계정에 저장되며, 나루 화면과 이용약관·개인정보처리방침 등 법적 문서에 적용한다. Litpage 화면에는 적용하지 않는다(DEC-101, DEC-113). 시스템을 고르면 기기의 설정을 따른다.
- **적용 범위**: 나루 화면과 이용약관·개인정보처리방침 등 법적 문서(FR-SHELL-002, FR-SHELL-003). Litpage 화면은 테마 적용 대상에서 제외한다(DEC-113).
- **측정 기준**: 프로필에서 세 가지 테마를 모두 선택할 수 있다. 계정에 저장된 테마는 다시 로그인하거나 다른 기기로 들어와도 유지되며, 시스템 모드의 화면은 해당 기기 설정을 따른다. 나루 화면과 새 창으로 연 법적 문서에 적용되고 Litpage 화면에는 적용되지 않는다. 로그인 전 적용 방식은 설계 이관이다.
- **출처 DEC**: DEC-101, DEC-113

#### NFR-USAB-003 접근성 WCAG 2.1 AA

- **내용**: 1차 화면은 WCAG 2.1 AA 기준을 따른다(DEC-102). 라이트·다크 두 테마 모두에 적용한다.
- **적용 범위**: 1차 화면. Litpage 화면과 법적 문서 등 화면별 적용 범위 및 검증 방식의 세부는 설계 이관([미확인], DEC-102).
- **측정 기준**: WCAG 2.1의 A·AA 성공 기준(예: 텍스트 대비 4.5:1, 키보드 조작, 대체 텍스트)을 주요 화면에서 충족하는지 확인한다. 라이트·다크 모드 각각에서 대비 기준을 확인한다. [미확인] 검증 도구·담당·합격 기준의 세부(설계 이관).
- **출처 DEC**: DEC-102

### 4.5 OPS — 운영

#### NFR-OPS-001 백업 주기

- **내용**: 서비스 데이터(회원 정보, 드라이브 파일)는 매일 백업하고, 백업은 30일이 지나면 자동 만료된다. 백업 범위는 회원 정보와 파일만이다. 공유·링크·설정은 백업하지 않으므로, 백업에서 복원하면 이들이 없을 수 있다(DEC-091). 이 점을 복원 절차와 안내에 명시한다. 이 백업은 사용자 휴지통(30일)과는 별개다. 백업에서 데이터를 복원하면, 복원 시점 이전에 이루어진 탈퇴와 휴지통 삭제를 다시 적용한다(DEC-083). 즉 복원으로 탈퇴 회원 데이터나 휴지통에서 삭제된 파일이 되살아난 채 남아서는 안 된다.
- **적용 범위**: 회원 정보, 드라이브 파일
- **측정 기준**: 매일 백업이 수행되고, 백업본이 30일이 지나면 자동으로 만료되는지 확인한다. 사용자 휴지통의 30일 자동 삭제 정책(DEC-019)과 섞어 적용하지 않는다. 백업에서 복원한 뒤, 복원 전에 탈퇴한 회원의 데이터(보관 30일이 지난 것)와 휴지통에서 삭제 처리된 파일이 다시 삭제 상태가 되는지 확인한다. [미확인] 복원을 누가 어떤 절차로 하는지, 복원 직후 재적용이 끝나기 전 접근을 막을지는 정해지지 않았다(설계 이관). 백업 범위는 회원 정보와 파일뿐이므로, 복원 뒤 공유·링크·설정이 없어도 이상이 아니며 복원 절차에서 그 사실을 안내하는지 확인한다(DEC-091).
- **출처 DEC**: DEC-046, DEC-083, DEC-091

#### NFR-OPS-002 로그 보관과 지표 집계 별도 보관

- **내용**: 로그는 30일 보관한다. 성공 지표(PRD §6, DEC-080)를 위한 집계 결과는 로그와 따로 보관한다(DEC-085). 로그가 30일 뒤 사라져도 집계 결과는 그 영향을 받지 않는다.
- **적용 범위**: 전체
- **측정 기준**: 로그가 30일간 보관되고, 그 이후에는 보관하지 않는지 확인한다. 지표 집계 결과는 로그와 다른 보관 대상으로 구분되어 있고, 로그 만료로 지워지지 않는지 확인한다. [미확인] 집계 결과의 보관 기간과 집계에 담는 항목은 정해지지 않았다. 집계 결과에 회원 식별 정보를 담는지도 정해지지 않았다(설계 이관).
- **출처 DEC**: DEC-044, DEC-085

#### NFR-OPS-003 관리자 감사 기록

- **내용**: 관리자가 회원을 정지·해제하거나 오픈소스를 숨김·노출하면 그 동작을 감사 기록으로 남긴다(DEC-104).
- **적용 범위**: FR-ADM-002, FR-ADM-003, BR-017
- **측정 기준**: 정지·해제·숨김·노출을 실행할 때마다 그 동작이 감사 기록으로 남는지 확인한다. [미확인] 기록 항목(누가·언제·무엇을 등)과 보관 기간, 로그 30일(NFR-OPS-002, DEC-044)을 따를지는 정해지지 않았다. 로그 30일 보관의 법적 적정성은 Q-081과 함께 정식 배포 전에 확인한다(Q-091).
- **출처 DEC**: DEC-104 (로그 보관은 DEC-044)

#### NFR-OPS-004 저장 용량 운영 경보

- **내용**: 서비스 전체의 저장 용량이 일정 수준을 넘으면 운영 경보를 낸다(DEC-105). 이는 운영자를 위한 경보이며, 회원의 업로드를 막지 않고 회원별 총용량 제한도 두지 않는다(DEC-010).
- **적용 범위**: 전체 (운영 요구. 연결할 FR 없음)
- **측정 기준**: 전체 저장 용량이 기준을 넘는 시점에 운영 경보가 나가는지 확인하고, 그때도 업로드가 막히지 않는지 확인한다. [미확인] 기준 수치, 경보를 받는 사람·방법은 정해지지 않았다(Q-092).
- **출처 DEC**: DEC-105 (총용량 제한 없음은 DEC-010)

### 4.6 COMP — 호환성

#### NFR-COMP-001 지원 장치·형태

- **내용**: 1차는 PC 웹 브라우저와 모바일 웹(반응형)을 지원하고, 모바일 앱은 지원하지 않는다.
- **적용 범위**: 전체
- **측정 기준**: 앱 스토어 설치형 앱 없이, PC와 모바일의 웹 브라우저로 1차 기능을 사용할 수 있다.
- **출처 DEC**: DEC-038

#### NFR-COMP-002 지원 브라우저와 버전

- **내용**: 공식 지원 브라우저는 최신 Chrome(PC·Android)과 최신 Safari(iOS·macOS)다. 대상은 PC 웹과 모바일 웹이다. 모바일 앱은 지원하지 않는다.
- **적용 범위**: 전체
- **측정 기준**: 최신 Chrome(PC·Android)과 최신 Safari(iOS·macOS)에서 1차 기능이 동작하는지 확인한다.
- **출처 DEC**: DEC-043 (환경 전제는 DEC-038)

### 4.7 I18N — 국제화·언어

#### NFR-I18N-001 한국어와 영어

- **내용**: 1차 화면 언어는 한국어와 영어다. 사용자에게 두 언어로 화면을 제공해야 한다.
- **적용 범위**: 전체 화면 문구 (공통 헤더·푸터, 홈, 드라이브, 로그인·탈퇴, 관리자, 비회원 링크 보기 안내, 프로필, 계정 설정). 이용약관·개인정보처리방침 등 법적 문서의 언어는 NFR-I18N-003(DEC-048)을 따른다.
- **측정 기준**: 주요 화면 문구를 한국어와 영어로 전환하거나 선택해 볼 수 있다. 기본값과 전환·유지 방식은 NFR-I18N-002를 따른다.
- **출처 DEC**: DEC-039

#### NFR-I18N-002 기본 언어와 전환 방식

- **내용**: 화면 언어를 아직 설정하지 않은 경우에는, 기기 언어가 영어면 영어로, 그 외에는 한국어로 시작한다(DEC-045). 프로필 화면에서 한국어 또는 영어로 설정한 뒤에는 그 언어를 계정에 저장해 다음 방문에도 유지한다(DEC-052, DEC-100). 기기 언어 규칙은 설정을 하기 전에만 적용한다. 로그인 화면에서도 언어를 전환할 수 있다. 로그인 전에 고른 언어와 계정 언어가 다르면 로그인 후 계정 언어를 따른다(DEC-110). 로그인 전 선택의 임시 저장 방식은 설계 이관이다. Litpage 화면도 나루 화면 언어에 맞춘다(DEC-100).
- **적용 범위**: 전체 화면 (FR-SHELL-003, FR-AUTH-001, FR-OSS-001)
- **측정 기준**: 설정 전에는 기기 언어 규칙으로 시작하는지, 설정한 뒤에는 다시 방문하거나 다른 기기로 들어와도 고른 언어가 유지되는지, 프로필에서 언어를 바꿀 수 있는지, 로그인 화면에서 언어를 전환할 수 있는지, Litpage 화면 언어가 나루 화면 언어와 같은지 확인한다. 로그인 전 선택과 계정 언어가 다르면 로그인 후 계정 언어로 표시한다(DEC-110).
- **출처 DEC**: DEC-045, DEC-052, DEC-100 (언어 범위는 DEC-039, 설정 위치는 DEC-047), DEC-110

#### NFR-I18N-003 법적 문서 한국어·영어

- **내용**: 이용약관·개인정보처리방침 등 법적 문서는 한국어와 영어로 모두 제공한다.
- **적용 범위**: 공통 푸터에서 여는 이용약관·개인정보처리방침 등 법적 문서(FR-SHELL-002, BR-021)
- **측정 기준**: 한국어 본문과 영어 본문을 모두 확인할 수 있다.
- **출처 DEC**: DEC-048 (화면 언어 범위는 DEC-039)

## 5. 추적 메모

- 0바이트 파일 차단과 파일당 1GB(1,073,741,824바이트) 한도(NFR-PERF-002)는 기능 요구 FR-DRV-003·BR-024와 같다. 총용량 제한 없음(DEC-010, REQ-017)과 구분해 적용한다.
- NFR→FR 연결(GAP-022)은 `traceability/matrix.csv`에 둔다. 특정 FR에 묶이지 않는 NFR(NFR-PERF-001, NFR-SEC-005, NFR-AVAIL-001, NFR-USAB-001, NFR-USAB-003, NFR-OPS-001, NFR-OPS-002, NFR-OPS-004, NFR-COMP-001, NFR-COMP-002, NFR-I18N-001)은 matrix에서 FR 칸을 "전역 요구"로 표시한다.
- 보안 NFR은 새로운 기술 수단을 지정하지 않으며, 이미 정해진 접근 통제·세션·데이터 보관 규칙을 비기능 기준으로 재진술한다.
